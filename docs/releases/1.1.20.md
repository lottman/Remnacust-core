# Remnacust Core 1.1.20

Исправлено удержание сессий Xera после отклонённых загрузок: слоты и таймеры освобождаются без удаления сессии, используемой параллельным корректным запросом. HTTP/3 применяет настроенный предел заголовков. Автоматический Firefox User-Agent согласует `rv` с версией ClientHello, сохраняя явные пользовательские значения.

Частичный HTTP/2-профиль поддерживает Chrome 155 на основании сравнения SETTINGS, окна и псевдозаголовков с официальным Chrome for Testing 155.0.8059.84. Проверка сертификатов и REALITY сохраняется. Формат Xera и VLESS credentials не меняются; прежние клиенты не обязаны менять конфигурацию.

Для проверенных H2-профилей устранён начальный арифметический рост TLS-записей. Ограниченная очередь объединяет уже готовые байты без ожидания заполнения; сохраняются обратное давление, deadlines и корректное TLS-закрытие. По умолчанию packet-up использует интервал 20–40 мс со средней точкой 30 мс; явные настройки сохраняются. Это не устраняет временной профиль приложения и не управляет TCP-сегментацией.

Исправлено игнорирование явных ограничений minVersion/maxVersion клиентом с uTLS. Проверяются допустимые значения и порядок границ, диапазон согласуется с возможностями отпечатка, несовместимое соединение отклоняется. Проверены implicit I/O, WebSocket, generic-клиент и ECH. Сервер, не соответствующий ранее игнорировавшейся политике, теперь не сможет согласовать запрещённую версию.

Исправлена очистка TCP, WebSocket и HTTP Upgrade при отказе до передачи соединения вызывающему коду. REALITY закрывает ранние отказы и сохраняет передачу соединения своему существующему spider-пути. Проверка явных версий TLS сохраняет выбранный ALPN WebSocket.

XDRIVE отменяет и дожидается фоновых операций WAL, slots и объявления сессии до освобождения хранилища. Закрытие listener завершает принятые соединения. На graceful flush соединения отводится 30 секунд либо более ранний write deadline; исчерпание бюджета возвращает ошибку. Ожидание завершения предполагает соблюдение backend-ом отмены контекста.

[Настройка допуска и пределы защиты](https://github.com/lottman/Remnacust-core/blob/v1.1.20/docs/XERA-HTTP.md): обычный padding не является секретом, общий маркер профиля не обеспечивает защиту от повторов после раскрытия, а согласование отдельных HTTP/2-полей не доказывает неотличимость от браузера или устойчивость к неизвестному ИИ-классификатору. Основа — официальный Xray v26.11.9, Go 1.27.4.

## English

Rejected Xera uploads release new session slots and timers without deleting a session used by another valid request. HTTP/3 enforces the configured header limit. Automatically generated Firefox User-Agent revisions match the selected ClientHello version while explicit values are preserved.

The partial HTTP/2 profile supports Chrome 155 after comparing SETTINGS, window and pseudoheader order with official Chrome for Testing 155.0.8059.84. Certificate and REALITY verification remain enabled. Xera framing and VLESS credentials are unchanged; existing clients do not require configuration changes.

Verified H2 profiles no longer use the initial arithmetic TLS record-size ramp. A bounded queue combines already-ready bytes without waiting to fill a batch; backpressure, deadlines and graceful TLS closure remain enforced. Default packet-up pacing samples 20–40 ms around a 30 ms midpoint; explicit settings are preserved. Application timing and TCP segmentation remain separate concerns.

Fixes ignored explicit uTLS minVersion/maxVersion bounds. Supported values and bound ordering are validated, the permitted range is intersected with the fingerprint, and incompatible connections are rejected. Verification includes implicit I/O, WebSocket, generic clients and ECH. A server outside a previously ignored policy can no longer negotiate a forbidden version.

TCP, WebSocket and HTTP Upgrade release owned sockets when setup fails before handoff. REALITY closes early failures while preserving transfer to its existing spider path. Explicit TLS version filtering preserves the requested WebSocket ALPN.

XDRIVE cancels and joins WAL, slot and session-announcement operations before releasing storage. Closing its listener closes accepted connections. Graceful connection flush has a 30-second budget or an earlier write deadline; exhaustion returns an error. Joining assumes the backend honors context cancellation.

[Admission and protection limits](https://github.com/lottman/Remnacust-core/blob/v1.1.20/docs/XERA-HTTP.md): ordinary padding is not a secret, a disclosed static profile marker can be replayed, and matching selected HTTP/2 fields does not establish browser indistinguishability or resistance to an unknown AI classifier. Based on official Xray v26.11.9 and Go 1.27.4.
